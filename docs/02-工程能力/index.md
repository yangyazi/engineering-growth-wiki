# 工程能力总览

当前认同的核心工程能力可以归纳为四项。它们不是互相独立的课程，而是在一个真实的软件开发任务中不断交织的能力。

<div class="grid cards" markdown>

-   **代码理解与构建**

    从陌生代码中找到结构和执行路径，并把需求转化成清晰、正确、可维护的实现。

    [:material-arrow-right: 查看能力说明](代码理解与构建.md)

-   **软件设计与抽象**

    划分职责和边界，管理依赖与变化，比较不同实现方案的成本。

    [:material-arrow-right: 查看能力说明](软件设计与抽象.md)

-   **问题分析与 Debug**

    通过现象、假设、证据和实验定位根因，而不是猜测或盲目修改。

    [:material-arrow-right: 查看能力说明](问题分析与Debug.md)

-   **系统运行与工程质量**

    理解程序运行和交付的完整环境，用测试、日志、监控和维护机制保证质量。

    [:material-arrow-right: 查看能力说明](系统运行与工程质量.md)

</div>

## 四项能力如何连接？

```text
理解现有系统与代码
        ↓
明确问题、需求和约束
        ↓
设计模块、接口和实现方案
        ↓
实现并控制代码变更
        ↓
测试、观察、Debug 和验证
        ↓
交付、维护、复盘
        ↺ 把经验带入下一次工程任务
```

这不是一次性线性流程。真实工作中经常需要往返：实现时发现需求理解有误，测试时发现设计不合理，运行时发现原先没有考虑的环境约束。

## 能力不是靠名词记忆形成的

例如，知道“依赖注入”“事务”“线程池”“索引”这些词，并不等于具备工程能力。能力体现在遇到具体问题时，能否：

1. 识别这个概念是否相关；
2. 理解它为什么存在；
3. 预测不同选择可能造成的结果；
4. 通过实验或运行证据验证判断；
5. 根据实际约束选择合适方案。

## 学习时的原则

- 以真实代码和工程问题为主线。
- 以基础知识解释观察到的现象。
- 以实际变更和验证检验理解。
- 以复盘沉淀可迁移的方法。
