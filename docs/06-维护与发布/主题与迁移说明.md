# 主题与迁移说明

## 当前技术选择

本站使用 **GitHub Pages + MkDocs Material**。它适合把 Markdown 内容组织成有导航、搜索、代码高亮和目录的文档站点。

## 一个需要提前知道的维护信息

截至 2026 年 11 月，Material for MkDocs 已进入维护模式：官方在 2026 年 11 月 5 日将生命周期**延长了六个月**，此后到 **2027 年 5 月 5 日** 为止只提供关键修复与安全更新，不再增加新功能。官方把 Zensical（同一团队、MIT 协议）作为后续方向，并明确不强制现有项目迁移。

这不意味着当前网站不能继续使用，也不需要现在立即迁移。但如果计划长期维护，应把内容和主题配置分开，未来关注迁移路径。

参考：

- [Zensical：2026 年 11 月更新（EOL 延长至 2027-05-05 的原始出处）](https://zensical.org/upcoming-changes/#material-for-mkdocs)
- [Material for MkDocs 官方 Changelog](https://squidfunk.github.io/mkdocs-material/changelog/)
- [Zensical 官网](https://zensical.org/)

## 本项目为迁移做了什么准备？

- 文章内容尽量使用标准 Markdown。
- 页面结构和导航集中在 `mkdocs.yml`。
- 自定义 CSS 集中在 `docs/stylesheets/extra.css`。
- 没有把核心知识内容写进主题模板或自定义 JavaScript。
- 页面之间使用相对 Markdown 链接。

## 未来迁移时

1. 先确认目标工具对当前 Markdown 扩展和导航配置的支持情况。
2. 在单独分支创建迁移实验，不直接覆盖现有发布版本。
3. 先迁移核心页面，检查目录、代码块、提示框、标签页和内部链接。
4. 执行构建和链接检查，再比较页面阅读体验。
5. 确认后再切换 GitHub Actions 部署工作流。

不要因为工具有维护周期就提前制造不必要的迁移工作。当前更重要的是把知识内容和训练过程真正积累起来。
