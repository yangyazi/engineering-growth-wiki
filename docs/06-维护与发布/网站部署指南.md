# 网站部署指南

本项目使用 MkDocs Material 将 Markdown 文档构建为静态网站，并通过 GitHub Actions 发布到 GitHub Pages。

## 第一步：创建仓库

在 GitHub 创建一个新仓库，例如 `engineering-growth-wiki`。GitHub Free 账号只有 **Public** 仓库可以使用 Pages，因此这里选 Public；也正因为网站公开可访问，不要把公司机密或个人敏感信息放进文章。

## 第二步：上传文件

把下载包解压，将项目根目录下的所有文件上传到仓库根目录。可以用 GitHub 网页的 Add file 上传，也可以在本地终端进入项目目录后执行：

```bash
git init
git add .
git commit -m "Initialize engineering growth wiki"
git branch -M main
git remote add origin https://github.com/<你的用户名>/<仓库名>.git
git push -u origin main
```

确认以下文件存在：

- `mkdocs.yml`
- `requirements.txt`
- `docs/index.md`
- `.github/workflows/deploy.yml`

默认分支使用 `main`。

## 第三步：启用 GitHub Pages

进入仓库：

`Settings → Pages → Build and deployment → Source → GitHub Actions`

选择 GitHub Actions 作为发布来源。

## 第四步：触发部署

将文件推送到 `main` 分支，或在 Actions 页面手动运行 `Deploy documentation to GitHub Pages`。

工作流会：

1. 检出代码；
2. 设置 Python 3.12；
3. 安装 `requirements.txt` 中的依赖；
4. 执行 `mkdocs build --strict`；
5. 上传构建结果并部署到 GitHub Pages。

## 第五步：访问网站

部署成功后，在仓库的 `Settings → Pages` 页面查看发布地址。项目仓库页面通常是：

`https://<你的 GitHub 用户名>.github.io/<仓库名>/`

## 后续更新

编辑 `docs/` 下的 Markdown 文件，修改 `mkdocs.yml` 中的导航（如有新增页面），提交并推送到 `main` 即可自动发布。

## 本地预览

需要 Python 3.11 或更新版本（`mkdocs-material` 9.8.x 的硬性要求）；macOS 自带的 `python3` 若为 3.9，请改用 3.11+ 的解释器创建虚拟环境。

```bash
python -m venv .venv
source .venv/bin/activate  # Windows PowerShell 使用 .venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
mkdocs serve
```

在浏览器访问 `http://127.0.0.1:8000/`。

本地构建检查：

```bash
mkdocs build --strict
```

`mkdocs.yml` 里开启了 `strict: true`：失效的内部链接、未登记进 `nav` 的页面都会让构建直接失败。构建失败时，先看报错指向的文件路径，再检查它是否与 `nav` 中的写法完全一致（包含大小写和中文标点）。
